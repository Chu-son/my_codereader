# テスト規約

## ツール

- 単体・コンポーネントテスト: Vitest + Testing Library（`jsdom`）。
- API モック: MSW。実際の GitHub API に接続するテストは書かない。
- E2E（任意）: Playwright。主要フローのスモークテストに限る。
- 実行: `npm run test`（CI では `--run`）。

## 対象と優先順位

| 対象 | 方針 |
| --- | --- |
| `lib` の純粋関数（`urlParser`, `searchUtils`, `fileUtils`） | **必須**。境界値と不正入力を含める |
| GitHub API クライアント | 必須。正常系と、エラー種別ごとの正規化（`rate_limit` など）を検証 |
| ストアのスライス | 必須。アクションの結果と永続化の `migrate` を検証 |
| コンポーネント | 主要な操作（読込、ファイルを開く、ブックマーク、設定変更）を検証 |
| E2E | リポジトリ読込 → ファイルを開く → 検索の最短経路 |

## 書き方

- ファイルは対象の隣に `*.test.ts(x)` として置く。
- `describe` は対象名、`it` は日本語で「〜のとき〜する」と書く。
- Testing Library はユーザー視点のクエリ（`getByRole`, `getByLabelText`）を優先し、実装詳細に依存しない。
- テストは独立させる。時刻・乱数・ストレージは各テストで初期化または固定する。

## 運用

- バグ修正には、再現する回帰テストを同じ PR で追加する。
- テストを通すためにテストを削除・スキップしない。`it.skip` は理由と期限を付ける。
- カバレッジの目標: `lib` と API クライアントは行カバレッジ 80% 以上。数値の達成自体を目的にしない。
