# UI / UX・アクセシビリティ規約

## タッチ操作（iPad 優先）

- タップ可能な要素は 44×44px 以上にする（`--touch-min-size`）。
- ホバーでしか見えない・使えない UI は作らない。
- ノッチや下部バーに配慮し、`env(safe-area-inset-*)` を使う。
- 長押し・スワイプなどのジェスチャーには、必ずボタンによる代替手段を用意する。
- 閉じる・削除などの行内ボタンも常に表示する（ホバーで出し分けない）。

## 画面構成

- 頻繁に使う移動操作（戻る・進む・ブックマーク・分割）は、下中央の親指ツールバーに置く。パネルの切替と検索・設定は左端のアクティビティレールに置く。
- 下中央は親指ツールバーが使う。ほかの浮遊 UI（通知など）は下中央に出さない。本文には `--toolbar-clearance` 分の下余白を空け、最終行が隠れないようにする。

## デザイントークン

- 色・余白・角丸・影は CSS 変数（デザイントークン）で定義し、コンポーネントでは変数か Tailwind のトークンを使う。`#1e1e2e` のような色の直書きは禁止。
- テーマは Catppuccin Mocha を基準にする。意味のある名前（`--bg-primary`, `--accent-blue`）で参照する。
- インラインスタイルは動的な値（幅、位置）に限る。

## アクセシビリティ

- クリック可能な要素は `<button>` / `<a>` を使う。`div` に `onClick` を付けない。
- アイコンのみのボタンには `aria-label` を付ける。
- フォーカスは常に可視にする（`outline` を消さない）。
- ダイアログ・ドロワーはフォーカストラップを持ち、Esc で閉じる。閉じたら元の要素へフォーカスを戻す。
- 色だけで状態を伝えない（アイコンやテキストを併用）。コントラスト比は WCAG AA 以上。
- タブやツリーには適切な `role`（`tablist` / `tree` など）と `aria-*` を付ける。

## 文言

- UI の文言は日本語。コンポーネントに直書きせず、定数ファイルに集約する。
- エラー表示は「何が起きたか」と「次にすべきこと」を 1 文ずつ示す。
- ローディング中・空・エラーの 3 状態を必ず設計する。
