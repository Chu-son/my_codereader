# GitHub API 規約

## クライアント

- GitHub API への通信は `shared/lib/github` の 1 箇所に集約する。コンポーネントやストアから `fetch` を直接呼ばない。
- 共通ヘッダー: `Accept: application/vnd.github+json`、`X-GitHub-Api-Version: 2022-11-28`。PAT があれば `Authorization: Bearer <PAT>` を付ける。
- すべての関数は `AbortSignal` を受け取れるようにする。

## レスポンス検証

- レスポンスは境界でランタイム検証（zod 等）してから型付けする。検証前の値に型アサーションで型を付けない。
- 想定外の形はエラーとして扱い、握りつぶさない。

## エラー

エラーは判別可能な型に正規化する。

| 種別 | 条件 | UI での扱い |
| --- | --- | --- |
| `rate_limit` | 403/429 で残量 0 | リセット時刻を表示し、PAT 設定を案内 |
| `not_found` | 404 | リポジトリ・ブランチ・パスが存在しない、または非公開と案内 |
| `unauthorized` | 401 | PAT が無効と案内 |
| `network` | 通信失敗 | 再試行ボタンを表示 |
| `unknown` | その他 | 汎用メッセージ。詳細は `console.error` のみ |

エラーメッセージに PAT やリクエストヘッダーを含めない。

## レート制限

- 未認証は 60 回/時、認証済みは 5,000 回/時。`x-ratelimit-remaining` を保持し、設定画面などで残量を表示する。
- コード検索 (`/search/code`) は PAT 必須。PAT 未設定時は検索 UI で案内し、リクエストしない。

## 大きなデータ

- Git Tree が `truncated: true` の場合は、ユーザーに一部のみ表示であることを通知する。
- バイナリ・巨大ファイルは本文を取得せず、プレースホルダー表示にする（上限サイズは定数で定義）。
- 同一セッション内で取得済みの本文は再取得しない。
