# 状態管理規約

## ストア設計

- Zustand のストアは **スライス** に分割する（`repository` / `tabs` / `search` / `bookmarks` / `settings` / `ui` など）。1 ファイルに全状態を詰め込まない。
- 状態の種類を分ける。
  - **サーバー由来**: ツリー、ファイル本文、検索結果（キャッシュ。永続化しない）
  - **ユーザー設定**: 折り返し、フォントサイズ、行間、PAT など（永続化する）
  - **ユーザーデータ**: ブックマーク、最近のリポジトリ（永続化する）
  - **一時的な UI 状態**: ドロワー開閉、選択中のペイン（永続化しない）
- アクションは状態と同じスライスに置き、名前は動詞で始める（`addBookmark`, `switchBranch`）。

## 購読

- コンポーネントでは **必ずセレクタ** で必要な値だけを購読する。複数値は `useShallow` を使う。
- `useAppStore()` を引数なしで呼ぶ（ストア全体の購読）ことは禁止。
- 派生値はセレクタで定義し、ストアに重複して持たない。

## 永続化

- `persist` には必ず `partialize` を指定し、永続化する項目をホワイトリストで明示する。
- `version` と `migrate` を必ず設定する。永続化する形を変えたら `version` を上げ、旧データを移行する。
- 永続化してよいのは「ユーザー設定」と「ユーザーデータ」のみ。ファイル本文、ツリー、検索結果、通信状態は禁止。
- `partialize` / `persist` のオプションに型アサーションを使わない（型エラーはそのまま直す）。
- localStorage のキーは `codereader:<domain>` 形式にする（例: `codereader:settings`）。
- PAT の保存先は [security.md](security.md) に従う。

## 非同期

- 非同期アクションは、状態を `idle` / `loading` / `success` / `error` で明示する。エラーは文字列ではなく正規化したエラー型で持つ。
- リポジトリやブランチを切り替えたら、進行中のリクエストを `AbortController` で中断する。遅れて届いた古いレスポンスで状態を上書きしない。
- 同じパスを取得中に再度開いたときは、重複リクエストを発行しない。
